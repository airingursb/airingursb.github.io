This is idea 8 of the root `Four bear stories` contract. The existing brown desk bear is the identity source (`public/bear-study/poster.png`, visually inspected). ## Atmosphere and audience
A tiny inventor's bench inside the normal blog, visibly a workshop before any explanatory copy is read. A visitor chooses a miniature experiment; the bear gives it an earnest test, gets a puff of smoke in its face, adjusts the machine, and succeeds. Real exhibit links sit beside the result. A hurried reader can use those links immediately. Keyboard, touch and motion-sensitive readers receive the same outcomes.

## Primitives and states
- WorkshopStage: transparent PNG poster with sized canvas for authored H3 atlas; idle, loading, working, settled, static and failure. Decorative artwork is hidden from accessibility. Two separated semantic object buttons align with the laptop/plant and open-book/panda. A third transparent 44px-minimum button covers the bear (39% left, 22% top, 24% width, 42% height) and replays the selected experiment. Labels are quiet DOM captions below the scene; native buttons are usable by keyboard and touch. They respond to one activation and never navigate automatically.
- ProjectChoice: two visible rule-separated choice buttons with index and title. aria-pressed communicates the selected project; clicking an object or its choice row has identical behavior. Active ink is accent, no pill or card fill. Directional arrows belong only to real navigation links.
- ProjectResult: ordinary article content with selected project title, concrete summary and real exhibit link. Performance status is screen-reader-only in a polite live region; the physical motion supplies visible feedback. The same real links remain available without JavaScript.
- PreviewShell: BaseLayout + SiteHeader; localized title, restrained acceptance label, return to preview hub and normal Playbook link; Chinese default and `/en/previews/bear-workshop/` localization. No production routes or existing production Workshop component change.

## Interaction and motion
One H3 `minimax-h3-max-turbo` master carries the entire physical sequence: acknowledge → screwdriver contact → switch → puff → wipe face → adjust dial → switch → steady bulb → resting satisfaction. Source/request/task/provenance remain under workshop output. Offline processing removes connected exterior white backing and recovers edge coverage from dark or colored interior samples, preserving cream muzzle, paper, panda and grey smoke. The lamp aura becomes warm translucent light. Camera correction uses a subpixel full-rail measurement, a continuous camera path, and a second rigid machine-base anchor. Premultiplied area resampling prevents white color spill and sampling-phase crawl. The complete bench front and outer props remain pixel-identical to the first frame; all 181 H3 character frames are retained in bounded sprite playback. No CSS substitute for the character, mechanism or smoke.

The first visible arrival starts one complete core test. Selection or tapping the bear after it settles replays that same test for either real project. The arrival and user activation share one start guard, including while media loads. Selection while playing is coalesced to the latest project; the current physical performance completes once and the result resolves to that selection. It never queues repeated plays or redirects. In reduced motion, arrival or selection shows the completed still without requesting the atlas and immediately exposes the corresponding result. Failure preserves a complete PNG pose and real links. Playback pauses outside viewport or while document is hidden, retaining elapsed progress; it does not catch up on return. Returning to view never starts a second automatic performance. No autoplay loop, audio, playback bar or permanent instructions. Changing narration is never visible on the page.

## Responsive and accessibility
At 375px scene and all text fit the 335px available width; the notebook stacks below the scene, while two project labels stay next to their physical objects. Hotspot targets remain 44px and separated. At 768/1280px the scene remains bounded, content uses two columns only where readable. No hover requirement. Selection feedback uses visible project text and aria-pressed; performance status is a screen-reader-only polite live region. Focus stays on the activated choice. Native links work without JS. `prefers-reduced-motion` changes are honored live. White fringe, crop extremes, canvas sizing and touch scroll receive visual checks in both themes.
